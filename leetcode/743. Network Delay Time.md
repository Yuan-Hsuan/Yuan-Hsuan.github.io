### The Bottleneck Observation
I will reduce the problem as a Single-Source Shortest Path (SSSP) problem on a directed weighted graph. Since we want to find the time it takes for a signal to reach all nodes, the answer will be the maximum value among all the shortest paths from the starting node K. 

### The Strategy
Because the edges have non-negative weights (delays), Dijkstra's Algorithm is the optimal choice.

To implement this efficiently, I will need three core components:
1. An Adjacency List to represent the graph and quickly fetch neighbors.
2. A Distance Array initialized to infinity to track the minimum time to reach each node.
3. A Min-Heap (Priority Queue) to always process the one with the shortest accumulated delay first.

### The Precise Execution

In the main loop, I repeatedly pop the node with the minimum delay from the heap.
1. Stale State Pruning: I first check if the popped distance is outdated. If it is, I skip it.
2. Eager Relaxation: For a valid node, I relax its outgoing edges. I calculate the new delay to its neighbors. If it's strictly smaller than their current recorded distance, I update the distance array immediately and push the new state into the heap. This prevents suboptimal paths from bloating the queue.
3. Early Exit: I keep a counter of unvisited nodes. The moment this counter hits zero, I can immediately return the current weight, as the Min-Heap guarantees it is the maximum of the shortest paths. If the queue becomes empty and nodes are still unvisited, I return `-1`.


**Complexity** (V = n nodes, E = times.size() edges)
- **Time — O(V + E log E):** 
Building the adjacency list and initializing the distance array takes $O(V + E)$. Each successful relaxation pushes one state, so the heap holds at most $O(E)$ entries. Every push/pop operation is $O(\log E)$.
  The initial $O(V)$ is maintained because even in a sparse graph (e.g., $E = 0$), the setup cost remains.
- **Space — O(V + E):** The adjacency list stores all $E$ edges and $V$ vertices. The distance array takes $O(V)$. Even with a lazy-deletion heap where stale entries are left in place (rather than decrease-key'd out), the priority queue will grow to at most $O(E)$ states. Thus, the total memory footprint is bounded by $O(V + E)$.

## 🛠️ Solution
```c++
class Solution {
public:
    int networkDelayTime(vector<vector<int>>& times, int n, int k) {
        vector<vector<pair<int, int>>> adj(n+1, vector<pair<int, int>>());
        for (auto time: times) {
            adj[time[0]].push_back({time[2], time[1]});
        }

        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq; 
        vector<int> dist(n+1, INT_MAX);

        // ✅ 標準初始化：起點距離設為 0
        dist[k] = 0;
        pq.push({0, k});

        while (!pq.empty()) {
            auto [w, node] = pq.top();
            pq.pop();
            
            // ✅ 阻擋 PQ 中的過期殘影 (Stale State)
            if (dist[node] < w) continue; 

            // ✅ 精準計數與提早結束
            n--;
            if (n == 0) return w;
            
            for (auto nei: adj[node]) {
                int nextW = w + nei.first;
                int nextNode = nei.second;
                
                // ✅ 積極更新 (Eager Relaxation)：在 Push 前就卡位！
                if (nextW < dist[nextNode]) {
                    dist[nextNode] = nextW;
                    pq.push({nextW, nextNode});
                }
            }
        }
        return -1;
    }
};
```
