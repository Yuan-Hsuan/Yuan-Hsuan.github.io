## 🚀 Pitch

### The Bottleneck Observation
The naive approach is to square every element and then sort the array, which takes $O(N \log N)$ time. However, this ignores the given property: the input array is already sorted.

### The Strategy: Two Pointers (Outside-In)
Because the array is sorted, the largest squared values will always be found at the extremes — either the most negative numbers on the far left or the most positive numbers on the far right. To optimize this to $O(N)$, we use two pointers starting from both ends and populate the result array strictly **from back to front** (largest to smallest).

### The Precise Execution
1. Initialize a result array of the same size as the input, and a pointer `p` at its last index.
2. Place `left` at index `0` and `right` at index `n - 1`.
3. In a while loop, compare the absolute values at `left` and `right`. Whichever is larger, square it, place it at `res[p]`, and decrement `p`.
4. Move the corresponding `left` / `right` pointer inward until they meet.

**Complexity**
- **Time — $O(N)$:** we traverse the input array exactly once.
- **Space — $O(1)$ auxiliary:** excluding the required output array, we only use a few integer pointers.

---

## 🛠️ Optimization (最佳化程式碼)
```cpp
class Solution {
public:
    vector<int> sortedSquares(vector<int>& nums) {
        
        int n = nums.size();
        vector<int> res(n);

        int left = 0;
        int right = n - 1;

        int index = n - 1;

        while (left <= right) {
            if (-nums[left] > nums[right]) {
                res[index--] = nums[left] * nums[left];
                left++;
            } else {
                res[index--] = nums[right] * nums[right];
                right--;
            }
        }
        
        return res;
    }
};
```
