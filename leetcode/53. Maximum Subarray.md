## 🎙️ Naive Solution
The naive approach is to check every possible subarray. Even if we optimize it by maintaining a running sum for each starting index, it still takes `O(N^2)` time. 

## 🚀 Pitch

### The Bottleneck Observation
If the current running sum of a subarray drops below zero, it is not necessary to expend the subarray. It will only decrease the value of any future elements we append to it. For instance, adding a positive number to a negative prefix will always yield a result smaller than the positive number itself. Therefore, a negative running sum should never be expanded to the right.

### The Strategy: Kadane's Algorithm (Greedy Approach)
Based on this observation, we can use a greedy approach, known as Kadane's Algorithm. The core idea is to maintain a `current_sum` and a `global_max`. We dynamically decide whether to extend the current subarray or start a completely new one based on whether the current running sum is positive or negative.

### The Precise Execution
1. I will maintain two variables: `current_sum` to track the running sum of the current subarray, and `global_max` to store the maximum sum found so far.
2. I will iterate through the array from left to right.
3. At each step, if the `current_sum` is negative, I will reset it to zero (effectively abandoning the previous subarray and starting fresh).
4. I then add the current number to `current_sum` and update `global_max` if `current_sum` is strictly greater.

**Complexity**

* **Time — $O(N)$:** We traverse the input array exactly once.
* **Space — $O(1)$:** We only use two integer variables to maintain our state, allocating no extra memory.

## 🛠️ Code Review

```cpp
class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        
        if (nums.empty()) return 0;

        // 💡 Initialize with the first element to handle all-negative arrays
        int res = nums[0];
        int sum = 0;
        for (int num: nums) {
            sum = sum < 0? num: sum+num;
            res = max(res, sum);
        }

        return res;
    }
};
```

1.  In this implementation, there is a critical defensive programming detail: **`global_max` must be initialized to `nums[0]` instead of `0`.** If the input array consists entirely of negative numbers (for example, `[-3, -5, -2]`), initializing `global_max` to `0` would incorrectly return `0`. By initializing it to the first element, we guarantee that the algorithm correctly returns the largest negative number, seamlessly handling this extreme edge case.
