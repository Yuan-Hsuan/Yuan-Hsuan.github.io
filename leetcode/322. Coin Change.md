### Naive Solution
To solve this, the naive solution is using Backtracking to explore every possible coin combination. However, its exponential time complexity is unacceptable for large amounts. Therefore, I will optimize this using Dynamic Programming.

### The Bottleneck Observation
Before diving into the code, I want to briefly explain why Dynamic Programming is the best fit for this problem. It fundamentally comes down to two properties: Optimal Substructure and Overlapping Subproblems.

### The Strategy
First, it exhibits optimal substructure. This means the optimal solution for a larger amount can be built directly from the optimal solutions of smaller amounts.
For example, to find the minimum coins for amount 10, if we decide to use a coin of 5, we simply take the guaranteed optimal result for amount 5, and just add 1 coin to it. The global optimum is formed by local optimums.
Second, it has overlapping subproblems. If we use a naive backtracking approach, we would recalculate the answer for the same intermediate amounts over and over again through different branches.
By using a bottom-up DP array to cache these intermediate results, we eliminate all redundant calculations and drop the time complexity from exponential to strictly $O(\text{amount} \times \text{coins})$.

### 🛠️ Solution
```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        // dp[a] = 湊出金額 a 的最少硬幣數；amount+1 當「無限大」哨兵（不可能超過 amount 枚）
        vector<int> dp(amount + 1, amount + 1);
        dp[0] = 0;

        for (int a = 1; a <= amount; a++) {
            for (int c : coins) {
                if (c <= a) {
                    dp[a] = min(dp[a], dp[a - c] + 1);
                }
            }
        }

        return dp[amount] > amount ? -1 : dp[amount];
    }
};
```
