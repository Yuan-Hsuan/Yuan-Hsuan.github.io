## 🎙️ Naive Solution
Iterate through every possible pair with two nested loops and check whether they add up to `target`.
That is **O(N^2)**, and it recomputes the same combinations over and over.

## 🚀 Pitch

### The Bottleneck Observation
I don't need to look at pairs at all. For each value there is exactly one other value that would
complete it — the **complement**, `target - current_value`. Once the complement is known, the whole
problem reduces to "have I seen this value before?".

### The Strategy: Hash Map (value → index)
A hash map answers that question in O(1), so I maintain a map of `value -> index` and check whether
the complement is already in it. That brings the overall time complexity down to **O(N)**.

### The Precise Execution
In any valid pair one index is always smaller than the other, so I only ever need to check the
**previously visited** numbers: the element with the larger index will naturally look back and find
its match, which is what guarantees a single pass never misses a pair. Each value goes into the map
only *after* I have checked for its complement.

**Complexity**
- **Time — O(N):** N = `nums.size()`; one pass, each hash-map lookup and insert is O(1).
- **Space — O(N):** the `unordered_map` stores up to N value→index entries.

---

## 🛠️ Optimization
```c++
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {

        unordered_map<int, int> mp;

        int n = nums.size();
        for (int i = 0; i < n; i++) {
            int complement = target - nums[i];
            if (mp.count(complement)) {
                return {mp[complement], i};
            }
            mp[nums[i]] = i;
        }

        return {-1, -1};
    }
};
```
