## 🎙️ Naive Solution
To solve this problem, I will use **Dynamic Programming**. Before diving into the code, I want to briefly explain why Dynamic Programming is the best fit for this problem. It fundamentally comes down to two properties: Optimal Substructure and Overlapping Subproblems.
We can achieve this by breaking the entire string matching problem down into smaller prefixes.

## The Bottleneck Observation
Let’s look at the three allowed operations:
* Delete: If we choose to delete a character from word1, the current edit distance is simply the edit distance of word1's previous prefix and word2's current prefix, plus 1.
* Insert: Similarly, inserting a character means we reference the edit distance of word1's current prefix and word2's previous prefix, plus 1.
* Replace: If we replace a character, we look back at the optimal distance where both prefixes were one character shorter, plus 1

## The Strategy: 
Because we would be repeatedly calculating these same prefix combinations in a recursive approach, it's a classic case of Overlapping Subproblems. That is where the dynamic programing work.
Therefore, I will implement a 2D DP matrix to gather the results from the smallest prefixes (even empty strings) all the way up to the full lengths of both words.

### The Precise Calculation / Execution
I will define a 2D matrix `dp` of size `(N+1) by (M+1)`.
Here, `dp[i][j]` represents the minimum edit distance between the first `i` characters of `word1` and the first j characters of `word2`.
By using `0` to represent an empty string, I can elegantly handle all edge cases. For instance, transforming any string of length `i` to an empty string simply requires `i` deletions, which perfectly initializes my 0th row and 0th column.

Next, I will iterate through both strings. At each step, I compare `word1[i-1]` and `word2[j-1]`:

* **If the characters match:** The cost is zero. We simply inherit the edit distance from the previous state without these two characters (`dp[i-1][j-1]`).
* **If they don't match:** I will take the minimum cost among three possible operations, plus `1` for the current operation:
1. **Replace:** Inheriting from `dp[i-1][j-1]`
2. **Delete (from word1):** Inheriting from `dp[i-1][j]`
3. **Insert (into word1):** Inheriting from `dp[i][j-1]`

**Complexity**
- **Time Complexity:** is $O(N \times M)$ because we compute every state exactly once.
- **Space Complexity:** is currently $O(N \times M)$ to store the entire DP table."

## 🛠️ Solution
```cpp
class Solution {
public:
    int minDistance(string word1, string word2) {

        int n = word1.length();
        int m = word2.length();

        if (n == 0 || m == 0) return max(n, m);

        vector<vector<int>> dp(n+1, vector<int>(m+1, 0));

        for (int i = 0; i <= n; i++) dp[i][0] = i;
        for (int j = 0; j <= m; j++) dp[0][j] = j;

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (word1[i - 1] == word2[j - 1]) {
                    dp[i][j] = dp[i - 1][j - 1]; 
                } else {
                    dp[i][j] = min({
                        dp[i - 1][j - 1], // Replace
                        dp[i - 1][j],     // Delete
                        dp[i][j - 1]      // Insert
                    }) + 1;
                }
            }
        }

        return dp[n][m];
    }
};
```
