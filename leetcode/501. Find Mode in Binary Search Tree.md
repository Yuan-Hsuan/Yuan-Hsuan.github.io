## 🎙️ Naive Solution
The naive approach is to use a hash map to count the frequencies of all elements, which takes $O(N)$ time and $O(N)$ auxiliary space. However, this completely ignores the properties of a Binary Search Tree.

## 🚀 Pitch

### The Bottleneck Observation
There is a core property of BSTs: an In-order traversal processes nodes in a strictly non-decreasing order. This means duplicate values will be naturally grouped together.

### The Strategy: Bottom-Up Recursion (Divide and Conquer)
I will perform a recursive In-order traversal while maintaining three state variables: a prev pointer, a current_freq, and a max_freq.

### The Precise Calculation / Execution
At each node, after exploring the left subtree, I will compare the current node with my prev pointer. If they hold the same value, I increment current_freq. If not, I reset current_freq to 1.

Next, I update my result array. If current_freq equals max_freq, I append the current value. If current_freq strictly exceeds max_freq, it means I've found a new mode—I will clear the result array, append the new value, and update max_freq.Finally, I update the prev pointer to the current node and explore the right subtree.

**Complexity**
- **Time — O(N):** We visit every node exactly once.
- **Space — O(log N):** We only use a few variables for our state machine. However, it's worth noting that the recursive call stack will consume $O(H)$ space, where $H$ is the height of the tree.

## 🛠️ Optimization (最佳化程式碼)
```cpp
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
private:
    vector<int> res;
    TreeNode* prev = nullptr;
    int freq = 0;
    int max_freq = 0;
    void inorder(TreeNode* root) {
        if (root == nullptr) return;

        inorder(root->left);
        if (prev != nullptr && prev->val == root->val) {
            freq++;
        } else {
            freq = 1;
        }

        prev = root;

        if (freq > max_freq) {
            res.clear();
            res.push_back(root->val);
            max_freq = freq;
        } else if (freq == max_freq) {
            res.push_back(root->val);
        }

        inorder(root->right);
    }
public:
    vector<int> findMode(TreeNode* root) {
        inorder(root);

        return res;
    }
};
```

1. You successfully utilized res.clear() instead of reallocating a new vector (e.g., res = {root->val};). This preserves the underlying memory capacity of the vector, converting a potential $O(K)$ reallocation penalty into an $O(1)$ zero-overhead reset.
