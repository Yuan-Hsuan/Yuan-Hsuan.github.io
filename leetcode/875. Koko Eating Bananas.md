## 🎙️ Naive Solution

The naive approach is to linearly scan every possible eating speed `k` starting from 1 up to the
maximum pile size `max(piles)`. For each speed, we iterate through all piles to calculate the total
hours needed. Since checking each speed takes O(N) time, this sequential search results in a highly
inefficient **O(N * M)** time complexity, where M is the maximum number of bananas in a single pile.

## 🚀 Pitch

### The Bottleneck Observation (單調性與線性掃描瓶頸)
The core bottleneck is the sequential search over possible speeds. We can optimize this by observing
the **monotonic property**: if Koko can finish at speed `k`, she can definitely finish at any speed
greater than `k`. This monotonicity allows us to replace the linear scan with a **Binary Search on
the Value Range** of possible speeds.

### The Strategy: Binary Search on Value (值域二元搜尋)
Instead of searching indices, we binary search the speed `k` between 1 and `max(piles)`. This
instantly reduces the time complexity from O(N * M) down to **O(N * log M)**, which efficiently
handles large input constraints.

### The Precise Calculation / Execution (精準的執行邏輯)
We use a standard binary search template. For each `mid` speed, we calculate the total hours. If
`hours > h`, it means we are too slow, so we move to the right half (`left = mid + 1`). Otherwise,
the speed is feasible, but we try to find a smaller one by moving to the left half (`right = mid`).

**Complexity**
- **Time — O(N log M):** binary search over speeds `1..max(piles)`, each check scans all `N` piles.
- **Space — O(1):** only the two bounds and a running `hours` counter, no extra structures.

## 🛠️ Optimization (資深工程師優化重點)

* **🛡️ 修正整數溢位 (Integer Overflow)**
  在計算 `hours` 的累加過程時，如果 `mid` 很小且 `h` 很大，總合非常容易超過 `int` 的上限。在 C++ 中必須將
  `hours` 宣告為 `long long`。

* **🌟 移除浮點數運算 (Avoid ceil)**
  `ceil((double)a / b)` 在底層會觸發昂貴的型別轉換與函數呼叫。使用純整數公式 `(a + b - 1) / b` 即可達到
  完全一樣的無條件進位效果，效能更高且精確。

```cpp
class Solution {
public:
    int minEatingSpeed(vector<int>& piles, int h) {
        int left = 1;
        int right = 0;
        for (int p : piles) right = max(right, p);

        while (left < right) {
            int mid = left + (right - left) / 2;
            long long hours = 0; // 🛡️ 防止累加時發生整數溢位

            for (int pile : piles) {
                // 🌟 使用整數運算代替 ceil((double)pile/mid)
                hours += (1LL * pile + mid - 1) / mid;
            }

            if (hours > h) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return left;
    }
};
```

## 🛡️ Defensive Coding (防禦性編程)

* **鴿籠原理攔截 (Impossible Case)**
  如果 `h < piles.size()`，因為 Koko 每小時最多只能吃一堆，她絕對不可能吃完。可以在開頭直接 `return -1`
  （雖然 LeetCode 測資保證 `h >= piles.size()`，但在實際面試中這是一個加分點）。

* **最大值快速掃描**
  使用 `for` 迴圈找最大值比 `*max_element` 有時更靈活，且能同時進行其他防護檢查。
