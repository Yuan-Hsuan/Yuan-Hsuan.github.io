## 🎙️ Naive Solution

The naive approach is to linearly scan every possible eating speed `k` starting from 1 up to the maximum pile size. For each speed, we iterate through all piles to validate if Koko can finish all bananas within H hours. Since checking each speed takes O(N) time, this sequential search results in a inefficient **$O(N \cdot M)$** time complexity, where $M$ is the maximum number of bananas in a single pile, which is too slow."

## 🚀 Pitch

### The Bottleneck Observation (單調性與線性掃描瓶頸)
The core bottleneck is the sequential search over possible speeds. We can optimize this by observing
the **monotonic property**: if Koko can finish at speed `k`, she can definitely finish at any speed
greater than `k`. This monotonicity allows us to replace the linear scan with a **Binary Search on the Value Range** of possible speeds.

### The Strategy: Binary Search on Value (值域二元搜尋)
Instead of searching indices, we binary search the speed `k` between 1 and `max(piles)`. This instantly reduces the time complexity from O(N * M) down to **O(N * log M)**.

### The Precise Calculation / Execution (精準的執行邏輯)
I will define the search space with left = 1 as the minimum possible speed, and right = max(piles) as the maximum necessary speed. At each step, I calculate the mid speed and run my $O(N)$ validation helper function.

**Complexity**
- **Time — O(N log M):** binary search over speeds `1..max(piles)`, each check scans all `N` piles.
- **Space — O(1):** only the two bounds and a running `hours` counter, no extra structures.

## 🛠️ Solution

```cpp
class Solution {
private:
    bool valid(vector<int>& piles, int h, int bph) {
        int index = 0;
        for (int i = 0; i < piles.size(); i++) {
            h -= (piles[i] + bph - 1)/bph;
            if (h < 0) return false;
        }

        return h >= 0;
    }
public:
    int minEatingSpeed(vector<int>& piles, int h) {

      if (h < piles.size()) return -1;

      int l = 1, r = 1;

      for (int pile: piles) {
          r = max(pile, r);
      }

      while (l < r) {
          int mid = (r-l)/2 + l;

          if (valid(piles, h, mid)) {
              r = mid;
          } else {
              l = mid + 1;
          }
      }

        return r;
    }
};
```

* **🌟 移除浮點數運算 (Avoid ceil)**
  `ceil((double)a / b)` 在底層會觸發昂貴的型別轉換與函數呼叫。使用純整數公式 `(a + b - 1) / b` 即可達到
  完全一樣的無條件進位效果，效能更高且精確。
* **最大值快速掃描**
  使用 `for` 迴圈找最大值比 `*max_element` 有時更靈活，且能同時進行其他防護檢查。

## 🛡️ Defensive Coding (防禦性編程)

* **鴿籠原理攔截 (Impossible Case)**
  如果 `h < piles.size()`，因為 Koko 每小時最多只能吃一堆，她絕對不可能吃完。可以在開頭直接 `return -1`
  （雖然 LeetCode 測資保證 `h >= piles.size()`，但在實際面試中這是一個加分點）。
