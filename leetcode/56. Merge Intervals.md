## 🎙️ Naive Solution
The naive solution would be to check every possible pair of intervals for overlaps and merge them iteratively. This unorganized checking would lead to an O(N^2) time complexity, which is highly inefficient.

## 🚀 Pitch
### The Bottleneck Observation (亂序帶來的多餘比較)
The main bottleneck of the naive approach is the random order of the intervals, which forces us to compare every single interval against all others. If we can establish a predictable sequence, we only need to look at adjacent elements.

### The Strategy: Sorting as a Pre-requisite (排序前置處理)
To optimize this, we first sort the intervals **based on their start times**. This guarantees that any potentially overlapping intervals will sit strictly adjacent to each other in the array. This sorting step dictates our overall time complexity, which will be O(N log N).

### The Precise Execution (精準的單次掃描)
After sorting, we initialize a result array. We can then do a single O(N) pass through the intervals. For each interval, we check if it overlaps with the **last merged interval in our result array** (i.e., current start <= previous end). If they overlap, we merge them by updating the previous interval's end to the maximum of both ends. If there is no overlap, we simply append the current interval to our result array. 

**Complexity**
- **Time — O(N log N):** sorting dominates; the merge is a single O(N) scan of adjacent intervals.
- **Space — O(N):** the output array holds up to every interval; sorting adds an O(log N) stack.

## 🛠️ Optimization (原始程式碼待優化區)

這裡紀錄你原本邏輯正確，但可以寫得更「優雅 (Clean)」的優化點：

1. **避免維護額外的 `start` 與 `end` 變數：**
   你原本用 `start` 和 `end` 來記錄狀態，導致迴圈結束後，還必須補寫一行 `res.push_back({start, end});`。如果我們直接把第一個區間塞進 `res`，然後利用 **`res.back()`** 直接修改，不僅邏輯更直覺，也完全消除了遺漏最後一筆資料的風險。
2. **避免無謂的記憶體拷貝 (Range-based for loop with `const reference`)：**
   原著寫法 `for (auto interval: intervals)` 每次迭代都會**複製**一整個 `vector<int>`。改成 `const auto& interval` 可以達成零拷貝 (Zero-copy)，大幅提升效能。

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        // 🛡️ 防禦性編程：你的這行寫得非常棒！
        if (intervals.empty()) return {};
        
        sort(intervals.begin(), intervals.end());

        vector<vector<int>> res;
        // 先將第一個區間放入結果陣列，作為比較的基準
        res.push_back(intervals[0]);

        for (int i = 1; i < intervals.size(); i++) {
            // 透過 res.back() 直接取得當前最後一個正在處理的區間
            if (intervals[i][0] <= res.back()[1]) {
                // 有重疊：更新最後一個區間的 end time
                res.back()[1] = max(res.back()[1], intervals[i][1]);
            } else {
                // 沒重疊：將新的區間作為獨立個體推入結果陣列
                res.push_back(intervals[i]);
            }
        }

        return res;
    }
};
```

## 🛡️ Defensive Coding (防禦性編程)
* 1. 異常輸入攔截 (Empty Input Check)：
你原本的 if (intervals.empty()) return {}; 是非常標準的 Senior 習慣，這在實務上防止了後續存取 intervals[0] 時發生 Segmentation Fault。
* 2. 詢問是否允許修改輸入參數 (Modifying Input Parameter)：
在白板面試寫下 sort(intervals.begin(), intervals.end()); 之前，你可以先主動問面試官：
"Is it acceptable to modify the input array in-place by sorting it? Or should I create a copy first to keep the input immutable?"
這句話一問出來，面試官立刻會知道你具備良好的 API 設計與記憶體安全意識！

### 💡 教練點評：
你的演算法底子非常紮實！把 `start` 和 `end` 的變數維護，改成直接操作 `res.back()`，這是一個**通用邏輯框架**。未來只要遇到需要「合併連續狀態」的問題（例如字串壓縮、連續區間交集），都可以優先考慮直接拿 `result array` 的最後一項來做比對，這會讓你的程式碼看起來極度老練。
