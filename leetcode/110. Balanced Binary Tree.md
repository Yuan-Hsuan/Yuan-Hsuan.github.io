## 🚀 Pitch

### The Bottleneck Observation
A height-balanced binary tree is one where, for **every** node, the absolute height difference between its left and right subtrees is at most 1. The naive solution traverses every node and calculates each subtree's height independently — but this top-down approach recomputes heights redundantly, leading to an $O(N^2)$ time complexity.

### The Strategy: Bottom-Up DFS (Post-order)
To optimize this to $O(N)$, we use a bottom-up DFS — a Post-order traversal (Left $\rightarrow$ Right $\rightarrow$ Node) — so we can calculate a node's height and check its balance at the exact same time.

### The Precise Execution
A DFS helper returns an `int` representing the height of the subtree:
1. If the current node is null, the height is `0`.
2. Recursively call DFS on the left child and the right child.
3. **Short-circuit logic:** if either child returns `-1` (our sentinel value for an unbalanced tree), or if the absolute height difference is strictly greater than 1, immediately return `-1` to propagate the failure upward.
4. Otherwise the current subtree is balanced → return its actual height `max(left, right) + 1`.

Finally, the tree is balanced iff the root's result is not equal to `-1`.

**Complexity**
- **Time — $O(N)$:** we visit every node exactly once.
- **Space — $O(H)$:** where $H$ is the tree height (the recursion stack depth) — $O(\log N)$ in the best case, $O(N)$ in the worst case (skewed tree).

## 🛠️ Optimization (最佳化程式碼)
```c++
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
private:
    bool res = true;
    int height(TreeNode* root) {

        if (root == nullptr || res == false) return 0;

        int left_height = height(root->left);
        int right_height = height(root->right);

        if (abs(left_height - right_height) > 1) {
            res = false;
            return 0;
        }

        return max(left_height, right_height) + 1;
    }
public:
    bool isBalanced(TreeNode* root) {
        
        height(root);

        return res;
    }
};
```

### 🛡️ Senior refinement — drop the class member, use a sentinel value
但資深工程師通常會極力避免為了單一遞迴函式去宣告 class-level 的變數。為什麼？因為這破壞了函式的 「純粹性 (Pure Function)」，在多執行緒 (Multi-threading) 環境下，如果兩個執行緒同時呼叫同一個 instance 的 isBalanced()，這個共用的 res 就會產生 Data Race。還記得我們之前提過的 「Sentinel Value (哨兵值 / 錯誤碼)」 技巧嗎？既然高度一定是大於等於 0 的正整數，我們完全可以把 height() 的回傳型別榨出雙重價值：回傳 $\ge 0$ 代表這是一棵平衡樹，且數值就是它的高度；回傳 -1 代表這棵樹不平衡 (作為 Error Code)。這也是為什麼業界在解這題時，更偏好完全不使用外部變數的寫法。

```cpp
class Solution {
private:
    int height(TreeNode* root) {
        if (!root) return 0;

        int left_height = height(root->left);
        // 如果左子樹已經不平衡，直接往上回傳 -1 (短路求值)
        if (left_height == -1) return -1; 

        int right_height = height(root->right);
        // 如果右子樹已經不平衡，直接往上回傳 -1 (短路求值)
        if (right_height == -1) return -1;

        // 檢查當前節點是否平衡，若不平衡回傳 -1
        if (abs(left_height - right_height) > 1) return -1;

        return max(left_height, right_height) + 1;
    }
public:
    bool isBalanced(TreeNode* root) {
        // 只要回傳值不是 -1，就代表整棵樹是平衡的
        return height(root) != -1;
    }
};
```
