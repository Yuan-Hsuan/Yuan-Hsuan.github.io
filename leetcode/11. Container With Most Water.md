## 🎙️ Naive Solution
The naive approach is to go through every possible pair of lines. For each combination, we calculate the area and track the maximum. This brute-force solution takes **O(N^2)** time complexity, which is highly inefficient.

## 🚀 Pitch

### The Bottleneck Observation
The capacity of the container is strictly bounded by two factors: the width between the two lines, and the height of the shorter line. If we start with the maximum possible width (the leftmost and rightmost lines) and move our pointers inward, the width will strictly decrease by 1 at each step.

### The Strategy: Two Pointers (Greedy Convergence)
Start with the widest possible container and walk the two pointers inward. At each step we must
decide which pointer to move, and we make that choice greedily based on which line currently caps
the area.

To have any chance of finding a larger area despite the decreasing width, we must find a taller boundary to compensate.
If we move the pointer pointing to the taller line, the bottleneck height of our container remains unchanged (still capped by the shorter line) or becomes even worse, while the width is guaranteed to shrink. Therefore, our only logical choice is to greedily move the pointer pointing to the shorter line inward, hoping to discover a taller boundary. This allows us to find the optimal container in O(N) time.

### The Precise Calculation / Execution

We initialize two pointers, left at index 0 and right at the last index. In each iteration:

1. We compute the current area using min(height[left], height[right]) * (right - left).

2. We compare the values of height[left] and height[right].

3. We move the pointer pointing to the shorter value inward. We repeat this process until the two pointers meet.

**Complexity**
- **Time — O(N):** N = `height.size()`; two pointers converge, each index visited at most once.
- **Space — O(1):** only the two pointers and a running maximum, no extra structures.

## 🛠️ Optimization (原始程式碼與微幅效能優化)

在面試中，寫出標準的雙指針可以拿到基本分。但如果你能寫出「指針跳躍優化 (Pointer Skipping)」，就能向面試官展示你對 CPU 運算與冗餘狀態剔除的極高敏感度：

* **💡 指針跳躍優化 (Pointer Skipping)**
  當我們決定移動矮板（例如 `height[left]`）時，如果移到下一個位置看到的板子比剛剛的還要矮，我們根本
  不需要重新計算面積，因為寬度縮小且高度變矮，面積一定會縮水。我們可以寫一個簡單的 `while` 迴圈直接
  跳過這些絕對無用的矮板！

```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int maxArea(const vector<int>& height) {
        // 🛡️ 防禦性編程：如果輸入長度小於 2，根本無法組成容器
        if (height.size() < 2) return 0;

        int left = 0;
        int right = height.size() - 1;
        int max_water = 0;

        while (left < right) {
            int current_left_height = height[left];
            int current_right_height = height[right];
            
            // 計算當前水量
            int current_height = min(current_left_height, current_right_height);
            max_water = max(max_water, current_height * (right - left));

            // 🌟 核心優化：移動矮板，並且自動「跳過」所有比當前矮板更矮的無用柱子
            if (current_left_height < current_right_height) {
                left++;
                while (left < right && height[left] <= current_left_height) {
                    left++;
                }
            } else {
                right--;
                while (left < right && height[right] <= current_right_height) {
                    right--;
                }
            }
        }

        return max_water;
    }
};
```

## 🛡️ Defensive Coding (防禦性編程)

* **唯讀傳參保護 (Const Reference)**
  將函式簽章改為 `const vector<int>& height`。這不僅能避免不必要的物件拷貝（這在大型系統中是效能殺手），
  還能向編譯器保證此函式絕對不會對輸入資料產生任何副作用 (Side-effect free)。

* **物理極端輸入攔截 (Physical Dimension Guard)**
  在函式開頭加入 `if (height.size() < 2) return 0;`。這能防止惡意測資或極端空陣列輸入時，導致
  `right = height.size() - 1` 出現負數索引進而造成記憶體越界的崩潰。
