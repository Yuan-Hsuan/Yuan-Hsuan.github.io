## 🎙️ Naive Solution
To find the shortest transformation sequence, modeling this problem as an unweighted graph and using **Breadth-First Search (BFS)** is the most natural approach. Every word is a node, and an edge exists if two words differ by exactly one character.

## 🚀 Pitch

### The Bottleneck Observation

The core bottleneck is: **How do we efficiently build these edges?**
The naive solution is to compare every word pair in our list. For each pair, we iterate through their characters to check if they differ by exactly one letter. If we have $N$ words of length $M$, this pairwise comparison takes **$O(N^2 \times M)$** time.

### The Strategy:

#### 1: Wildcard Precomputation (通配符預處理)
To optimize this, I will use a **pattern-matching approach (or wildcard approach)**. For each word, I can generate its intermediate states by replacing each character with a wildcard (e.g., "hot" becomes "*ot", "h*t", "ho*"). I will use a Hash Map to map these intermediate patterns to all words that can be formed from them.

**Complexity**
- **Time:** This reduces the time complexity to **$O(N \times M^2)$**, allowing us to find neighbors in $O(1)$ time per state. 
- **Space :** The space complexity is a heavy **$O(N \times M^2)$** because we must store every intermediate state, which can lead to severe memory bloat.

#### 2: On-the-fly Character Substitution (動態字元替換)
To optimize the massive memory overhead, we can drop the precomputation entirely. 
When we pop a word from the BFS queue, we dynamically substitute each of its characters with all 26 lowercase English letters. We then check if this newly generated word exists in our original dictionary (stored as a Hash Set).
**Complexity**
- **Space:** The space complexity drops to **$O(N \times M)$** since we only store the original words. The time complexity becomes **$O(N \times 26 \times M^2)$**.

### The Precise Execution

#### 1: Wildcard Precomputation (通配符預處理)
First, I will precompute the dictionary. Then, I will initialize a queue for the BFS, starting with the `beginWord` and a step count of 1. For each word popped from the queue, I will generate its intermediate states, look up the Hash Map to find all adjacent words, and push them into the queue. 

#### 2: On-the-fly Character Substitution (動態字元替換)
First, I will load the entire `wordList` into a Hash Set to enable $O(1)$ lookups. Then, I will initialize a queue for the BFS, starting with the `beginWord` and a step count of 1. 
For each word popped from the queue, I will dynamically generate all possible neighbors by substituting each of its characters with all 26 lowercase English letters. 
If a generated word matches the `endWord`, we immediately return the result. If it exists in the Hash Set, I will push it into the queue and **immediately erase it from the Set**—this elegantly serves as marking the node as visited while simultaneously pruning our search space.

## The Final Trade-off

Both optimizations successfully avoid the naive $O(N^2)$ trap, but they offer a classic Space vs. Time trade-off. 
If the character set is massive (like Unicode), **Approach 1** is required to avoid iterating through thousands of characters. However, given the specific constraint of this problem—only 26 lowercase English letters—**Approach 2 is overwhelmingly better in practice**. It saves a massive amount of memory (preventing Out-Of-Memory errors) while maintaining an almost identical operational speed. Therefore, I will implement Approach 2.

## 🛠️ Code Review

#### 1: Wildcard Precomputation (通配符預處理)
```cpp
class Solution {
public:
    int ladderLength(string beginWord, string endWord, vector<string>& wordList) {

        // 🛡️ Defensive early exit: Check if endWord is in the dictionary
        unordered_set<string> dict(wordList.begin(), wordList.end());
        if (!dict.count(endWord)) return 0;

        unordered_map<string, vector<string>> umap;

        for (const string& str: wordList) {
            for (int i = 0; i < str.length(); i++) {
                string s = str;
                s[i] = '#';
                umap[s].push_back(str);
            }
        }

        unordered_set<string> visited;
        queue<string> q;
        q.push(beginWord);
        visited.insert(beginWord);
        int res = 2;
        while (!q.empty()) {
            int size = q.size();
            for (int k = 0; k < size; k++) {
                string str = q.front();
                q.pop();
                for (int i = 0; i < str.length(); i++) {
                    string s = str;
                    s[i] = '#';

                    if (umap.count(s)) {
                        // 🛡️ Use const reference to prevent deep copies
                        for (const string& word: umap[s]) {
                            if (word == endWord) return res;
                            
                            if (visited.count(word)) continue;
                            
                            visited.insert(word);
                            q.push(word);
                        }
                        // 🌟 Graph Pruning: Erase the intermediate state to speed up future lookups
                        umap.erase(s);
                    }
                }
            }
            res++;
        }

        return 0;
    }
};
```


### 1. Defensive Early Exit (The endWord Check)

"Before allocating memory for the Hash Map or starting the BFS, we should defensively check if the endWord even exists in the wordList. If it doesn't, a transformation is fundamentally impossible, and we can immediately return 0. This saves us from building an expensive graph for a guaranteed-to-fail scenario."

### 2. The Hidden Deep Copy Trap
In your inner loop, you wrote: for (string word: umap[s])

"In C++, writing for (string word : umap[s]) triggers a deep copy of the string for every single adjacent node we check. In a dense graph, this causes severe Memory Bloat and Time Limit Exceeded (TLE). We must defend against unnecessary allocations by using a const reference: for (const string& word : umap[s])."

### 3. The "Graph Pruning" Optimization (Erasing used wildcard patterns)

"While the visited set prevents processing the same word twice, we can optimize further. Once we expand an intermediate state (e.g., #ot), we retrieve all words connected to it. We will never need to use this specific wildcard state again because any word reached through it later would result in a strictly longer path. By actively erasing the wildcard key from the map after its first use (umap.erase(s)), we drastically prune the graph and prevent redundant iterations in future levels."

#### 2: On-the-fly Character Substitution (動態字元替換)
```cpp
class Solution {
public:
    int ladderLength(string beginWord, string endWord, vector<string>& wordList) {
        unordered_set<string> unvisited(wordList.begin(), wordList.end());
        if (!unvisited.count(endWord)) return 0;

        queue<string> q;
        q.push(beginWord);
        unvisited.erase(beginWord);

        int res = 1;
        while (!q.empty()) {
            int size = q.size();
            for (int i = 0; i < size; i++) {
                string curr = q.front();
                q.pop();
                for (int j = 0; j < curr.length(); j++) {
                    char original_char = curr[j];

                    for (char c = 'a'; c <= 'z'; c++){
                        curr[j] = c;
                        if (unvisited.count(curr)) {
                            if (curr == endWord) return res + 1;
                            q.push(curr);
                            unvisited.erase(curr);
                        }
                    }
                    curr[j] = original_char;
                }
            }
            res++;
        }

        return 0;
    }
};
```
