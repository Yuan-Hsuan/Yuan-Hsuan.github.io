## 🎙️ Naive Solution
The naive solution is to generate every possible subarray and check if it contains at most two distinct types of fruit. Generating subarrays takes O(N^2) and validating them takes O(N), leading to an unacceptable O(N^3) time complexity. 

## 🚀 Pitch
### The Bottleneck Observation (單調性觀察)
The brute-force approach ignores a key property: if a subarray is already invalid (contains more than 2 types of fruit), extending it further to the right will never make it valid again. This monotonic property strongly suggests a **Sliding Window** approach.

### The Strategy: Sliding Window with Frequency Map
I will abstract this problem into finding the **"Longest contiguous subarray with at most 2 distinct elements."** 
To achieve an optimal O(N) time complexity, I will use a Sliding Window controlled by two pointers (`left` and `right`), alongside a Hash Map to track the frequencies of the fruit types currently in our window.

### The Precise Execution
As the `right` pointer expands the window, we add the current fruit to our Hash Map and increment its frequency. 
When the size of our Hash Map exceeds 2 (meaning we've collected 3 distinct types), our window becomes invalid. We then use an inner `while` loop to aggressively shrink the `left` pointer, decrementing the frequency of the outgoing fruits. Once a fruit's frequency drops to 0, we explicitly remove it from the Hash Map to restore validity. Finally, we update our global maximum window size.

**🌟 Bonus: Extensibility (Senior Insight)**
While we could strictly use two variables to track the two fruits, using a Hash Map is much more scalable. If the product requirements change tomorrow to allow 3 or K baskets, our algorithm logic remains exactly the same—we just change the constraint condition from `> 2` to `> K`.

**Complexity**
- **Time — O(N):** Both `left` and `right` pointers traverse the array at most once.
- **Space — O(1):** The Hash Map will store a maximum of 3 elements at any given time, which takes strictly constant space.

## 🛠️ Optimization (最佳化程式碼)
```cpp
class Solution {
public:
    int totalFruit(vector<int>& fruits) {

        int res = 0;
        int left = 0;

        unordered_map<int, int> basket;

        for (int right = 0; right < fruits.size(); right++) {

            basket[fruits[right]]++;
            
            while (basket.size() > 2) {
                basket[fruits[left]]--;
                if(basket[fruits[left]] == 0) {
                    basket.erase(fruits[left]);
                }
                left++;
            }
            res = max(res, right - left + 1);
        }

        return res;
    }
};
```
## 💡 教練的進階點評 (Senior Code Review: The "Non-Shrinking Window" Trick)
你現在的寫法是業界最標準的「萬用滑動視窗模板」，邏輯極度嚴密。但身為你的面試教練，我想傳授你一個在外商 Coding 面試中，能讓面試官眼睛一亮的極致效能黑客技巧 (Advanced Optimization)。在你的寫法中，當視窗不合法時，我們用 while 迴圈無情地收縮 left，直到視窗再次合法。但是，這題我們只在乎「歷史最大長度 (Maximum Length)」。

這意味著什麼？這意味著我們的視窗根本不需要縮小！當視窗不合法時，我們只需要把整個視窗「平移」就好（也就是 left 和 right 同時前進一步），讓視窗保持在歷史最大長度，直到它遇到能讓它變得更大的新組合。
```cpp
class Solution {
public:
    int totalFruit(vector<int>& fruits) {
        int left = 0;
        unordered_map<int, int> basket;

        for (int right = 0; right < fruits.size(); right++) {
            basket[fruits[right]]++;
            
            // 🌟 神級優化：把 while 改成 if
            // 因為我們只在乎「最大長度」，視窗不合法時，我們平移視窗 (left++ 且 right 迴圈也會 ++)
            // 視窗的大小永遠不會縮小，只會維持現有最大值，或者變得更大！
            if (basket.size() > 2) {
                basket[fruits[left]]--;
                if(basket[fruits[left]] == 0) {
                    basket.erase(fruits[left]);
                }
                left++;
            }
        }

        // 結束時，right 剛好是 fruits.size()，減去 left 就是整個遍歷過程中的最大視窗長度
        return fruits.size() - left;
    }
};
```
