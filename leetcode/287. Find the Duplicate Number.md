## 🎙️ The Senior Pitch: From Station to Floyd's

### 1. The "Sorting Station" Intuition (If mutation is allowed)

"If we were allowed to modify the input array, I would use a **Cyclic Sort** approach. Since the values are strictly between `1` and `N`, we can treat index `0` as a 'sorting station.' We can continuously swap the number at index `0` to its correct index until we find a collision—meaning the target index already holds the same value. This gives us $O(N)$ time and $O(1)$ space."

### 2. The Constraint Pivot (Respecting Immutability)

"However, the problem constraints explicitly state that we **must not modify the array**. The swap approach mutates the state, which is a red flag in systems where the input data might be read-only or shared across threads. Therefore, we need a zero-mutation strategy."

### 3. The Graph Abstraction

"To solve this in strictly $O(1)$ auxiliary space without mutation, we can abstract the array into a **Directed Graph (Linked List)**. By treating the array index as the current node and the array value as the pointer to the next node (`next = nums[i]`), any duplicate number will naturally form a cycle with multiple pointers leading into it."

### 4. The Optimal Execution: Floyd's Algorithm

"To find the entrance of this cycle—which is our duplicate number—I will leverage **Floyd's Cycle-Finding Algorithm**.

1. **Phase 1 (Detect Intersection):** I will initialize a `slow` pointer moving one step (`nums[slow]`) and a `fast` pointer moving two steps (`nums[nums[fast]]`). Because a cycle exists, they are guaranteed to intersect.
2. **Phase 2 (Find Entrance):** Once they meet, I will reset the `slow` pointer back to the start (`0`). Then, I will move both pointers at the exact same speed (one step at a time). The exact node where they collide again is mathematically proven to be the cycle's entrance, revealing our duplicate number."
