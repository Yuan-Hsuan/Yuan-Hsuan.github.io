## 🚀 Pitch

### The Strategy: Backtracking
I'd model this as a backtracking problem. The problem wants **every** valid address, so I have to
walk through each one. Also, an address holds at most twelve digits, so anything longer returns
immediately and the time complexity stays tiny.

### The Precise Execution
To implement the backtracking, at each step:

- **The state.** I would carry two values down: `start`, the index where the current segment
  begins, and `path`, the segments I've already committed to.
- **The decision.** I decide **how many characters the current segment takes**.
- **The options.** I have three: 1, 2, or 3 characters.
- **The undo.** After each call returns, I pop the last segment off the path, so the next choice
  starts from the same state the previous one did.

To finalize:

- **The record.** When I've placed four segments **and** `start` has reached the end of the string,
  I add the path to the answer.

To optimize it, I return early when:

- **The pruning.** A segment has a leading zero, or its value falls outside the range 0 to 255.
  Also, if there are too many characters left to build a valid address — say only 2 segments left
  to build but 7 characters remaining — I return early.

**Complexity**
- **Time — $O(M^N \cdot N)$:** Strictly speaking, for a standard IPv4 address the time complexity
  is bounded by a constant $O(1)$, because the maximum length is 12 characters. However, if we
  generalize this to $N$ segments where each segment has a maximum of $M$ digits, the recursion
  tree has a depth of $N$ and a branching factor of $M$. This gives us at most $O(M^N)$ valid
  combinations. At the base case, joining the strings takes $O(M \cdot N)$ time. Therefore, the
  generalized time complexity is $O(M^N \cdot N)$.
- **Space — $O(M \cdot N)$:** Similarly, the practical space complexity is $O(1)$ due to the fixed
  constraints. In a generalized scenario, the space complexity is $O(M \cdot N)$. This accounts for
  the recursion call stack, which goes up to $O(N)$ deep, and the array we use to store the current
  segments, which holds up to $N$ strings of length $M$. Generating the final joined string also
  takes $O(M \cdot N)$ space.

## 🛠️ Solution
```c++
class Solution {
private:
    vector<string> res;
    // 1. 獨立的驗證模組：乾淨、好維護
    bool isValid(const string& s, int start, int len) {
        // 處理長度、前導零、數值範圍...
        string str = s.substr(start, len);
        if (str[0] == '0' && str != "0") return false;
        int num = stoi(str);
        return num >= 0 && num < 256;
    }

    // 2. 標準的回溯函數
    void backtrack(int start, vector<string>& path, const string& s) {
        // Base Case：層數滿了
        if (path.size() == 4 && start == s.size()) {
            // 唯一一次的字串拼接
            res.push_back(path[0] + "." + path[1] + "." + path[2] + "." + path[3]);
            return;
        }

        // 提早剪枝 (你的數學邏輯)
        int remainingChars = s.size() - start;
        int remainingSegments = 4 - path.size();
        if (remainingChars > remainingSegments * 3 || remainingChars < remainingSegments) return;

        // Recursive Step
        for (int i = 1; i <= 3 && start + i <= s.size(); i++) {
            if (isValid(s, start, i)) {
                path.push_back(s.substr(start, i)); // 做選擇
                backtrack(start + i, path, s);      // 進入下一層
                path.pop_back();                    // 撤銷選擇 (Backtrack)
            }
        }
    }
public:
    vector<string> restoreIpAddresses(string s) {
        vector<string> path;
        backtrack(0, path, s);
        return res;
    }
};
```
