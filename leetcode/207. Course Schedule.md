## 🎙️ Naive Solution
A naive approach might involve standard DFS to check every single path for a cycle, but without proper state management (like tracking visited and currently-visiting nodes), this can easily lead to redundant processing and TLE (Time Limit Exceeded).

## 🚀 Pitch
### The Bottleneck Observation (問題模型化)
The core challenge is determining if a valid sequence of dependent tasks exists. We can naturally model this as a **Directed Graph**, where each course is a node, and a prerequisite requirement forms a directed edge (Course A -> Course B). The problem then mathematically reduces to **Cycle Detection**—if a cycle exists, it's impossible to finish all courses.

### The Strategy: Topological Sort via Kahn's Algorithm (拓樸排序策略)
To solve this efficiently, I will use **Topological Sorting based on Kahn's Algorithm** (Breadth-First Search). By traversing the graph level by level, starting from courses that have no prerequisites, we can ensure a valid topological order and check if the graph is a Directed Acyclic Graph (DAG).

### The Precise Execution (精準的執行邏輯)
1. **Graph Construction:** First, I will build an **Adjacency List** from the input pairs for efficient neighbor lookups, and an **In-Degree array** to track how many prerequisites each course has.
2. **Queue Initialization:** I will push all courses with an in-degree of `0` (meaning they have no prerequisites) into a Queue.
3. **BFS Traversal:** While the Queue is not empty, I will pop a course, conceptually "take" it, and increment a `processedCourses` counter. Then, I will decrement the in-degree of all its neighboring courses. If a neighbor's in-degree hits `0`, it means all its prerequisites are fulfilled, so I push it into the Queue.
4. **Final Verification:** In the end, if `processedCourses` equals `numCourses`, we successfully took all courses. If not, a cycle exists (its nodes never reach in-degree `0`, so they never enter the queue).

**Complexity**
- **Time — O(V + E):** V = `numCourses`, E = number of prerequisites. Building the graph touches every
  edge once; then each node enters and leaves the queue exactly once while each edge is relaxed once.
- **Space — O(V + E):** the adjacency list stores all edges, plus the in-degree array and the queue
  (both O(V)).

## 🛠️ Optimization (最佳化程式碼)
```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // 🛡️ 防禦性編程：如果沒有任何先修限制，直接回傳 true，節省建圖開銷
        if (prerequisites.empty()) return true;

        vector<int> indegree(numCourses, 0);
        vector<vector<int>> adj(numCourses);

        // 🌟 Senior 效能優化：使用 const auto& 避免複製整個 vector<int>
        for (const auto& order : prerequisites) {
            int course = order[0];
            int pre = order[1];
            adj[pre].push_back(course);
            indegree[course]++;
        }

        queue<int> q;
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) q.push(i);
        }

        int taken = 0;

        while (!q.empty()) {
            int curr = q.front();
            q.pop();
            taken++; // 放在 pop 之後直接計算，邏輯更緊湊

            // course 只是基本型別 int，這裡直接用 int 即可
            for (int course : adj[curr]) {
                indegree[course]--;
                if (indegree[course] == 0) q.push(course);
            }
        }

        return taken == numCourses;
    }   
};

```

## 🛡️ Defensive Coding & Senior Moves

1. **Zero-Copy Iteration (零拷貝走訪)：**
原本寫作 `for (auto order: prerequisites)`，這會導致每次迴圈都**深拷貝 (Deep Copy)** 一個 `vector<int>`，如果邊非常多，效能損耗極大。改為 `for (const auto& order : prerequisites)`，直接拿 Reference，時間與記憶體效能瞬間提升，這是 C++ 面試官必看的細節！
2. **Early Return (提早結束)：**
加上 `if (prerequisites.empty()) return true;`。當沒有任何依賴關係時，不需要浪費時間建立 `indegree` 和 `adj`，展現你對系統資源邊界的敏銳度。
