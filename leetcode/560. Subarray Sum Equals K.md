## 🎙️ Naive Solution
The naive solution is to check every possible subarray to see if its sum equals K. Generating all possible subarray and summing them takes O(N^3) time. 

## 🚀 Pitch
### The Bottleneck Observation (排除滑動視窗)
When we hear "subarray sum", the **Sliding Window** technique usually comes to mind. However, since the input array can contain negative numbers, the running sum is **not monotonic** (it doesn't strictly increase or decrease). This means we wouldn't know when to shrink or expand our window. Therefore, Sliding Window is not our way. 

### The Strategy: Prefix Sum with Hash Map (前綴和與頻率映射)
To achieve an optimal O(N) time complexity, I will use the **Prefix Sum** technique combined with a **Hash Map**. 
The mathematical core of this approach is: if the difference between the `current_prefix_sum` and a `previous_prefix_sum` equals `K`, it means the subarray strictly between these two arrays sums to `K`. 

### The Precise Execution
As I iterate through the array, I will maintain a running `current_sum`. 
At each step, I will calculate the target value we are looking for `current_sum - K`. 
I will then query the Hash Map to see how many times this `target` has appeared in the past. If it exists, I add its frequency to my result count. Finally, I record the `current_sum` into the Hash Map and continue.

**Complexity**
- **Time — O(N):** We iterate through the array exactly once, and Hash Map lookups take O(1) on average.
- **Space — O(N):** In the worst-case scenario, every prefix sum is unique, requiring O(N) space in the Hash Map.

---

## 🛠️ Optimization (最佳化程式碼)
```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> prefix_sum;
        prefix_sum[0] = 1;

        int res = 0;
        int sum = 0;
        for (int num: nums) {
            sum += num;
            res += prefix_sum[sum - k];
            prefix_sum[sum]++;
        }
        return res;
    }
};
```

## 🚨 Senior Code Review：隱形的 Hash Map 污染 (The Implicit Insertion Trap)
請看這行：`res += prefix_sum[sum - k];`。在 C++ 的 `std::unordered_map` 中，當你用 `operator[]` 去存取一個**不存在的 key** 時，它不會回傳 null 或報錯，而是會**自動創建這個 key 並賦予預設值 0**。

這意味著：如果大部分情況 `sum - k` 都不存在，你的 Map 會被塞滿大量無用的 `(sum - k, 0)` 鍵值對——造成記憶體浪費 (memory bloat)；當 Map 裝滿時還會觸發昂貴的 rehashing，讓你的 O(N) 效能大幅下降。

🛠️ **防禦性寫法 (Defensive C++)**：永遠在讀取前先檢查 key 是否存在，用 `.count()` 或效能最高的 `.find()`。

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> prefix_sum;
        prefix_sum[0] = 1; // 🛡️ 完美的 Base Case 防禦

        int res = 0;
        int sum = 0;
        for (int num : nums) {
            sum += num;
            
            // 🛡️ 確定存在才讀取，避免隱式插入污染 Map
            if (prefix_sum.count(sum - k)) {
                res += prefix_sum[sum - k];
            }
            
            prefix_sum[sum]++;
        }
        return res;
    }
};
```
