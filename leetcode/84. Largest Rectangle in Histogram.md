## 🎙️ Naive Solution
The naive solution for this problem would be to check every possible combination of left and right
boundaries and find the shortest height between them, which gives us an **O(N^3)** time complexity.

## 🚀 Pitch

### The Bottleneck Observation
We can optimize by focusing on a key observation: 
1. Height Constraint: the height of any rectangle is strictly determined by the shortest bar inside it. This means as we iterate through the histogram from left to right, whenever we encounter a shorter bar, the taller bars before it can no longer be extended to the right. For example, if the heights are `[2, 1, 5, 6]`, the moment we hit the `1`, we no longer need to look back at the `2` because `1` becomes the new bottleneck.
2. Width Expansion: If we treat every single bar as the potential "bottleneck height" of a rectangle, its maximum width is strictly bounded by the **first shorter bar to its left** and the **first shorter bar to its right**. 

### The Strategy: Monotonic Increasing Stack
We use this observation to design an O(N) algorithm with a Monotonic Increasing Stack. The stack will store the indices of the bars. Instead of constantly looking back, we only keep track of heights in increasing order. 

### The Precise Calculation / Execution
During the iteration, if the current bar is taller than the stack's top, I simply push its index. 
However, if the current bar is shorter, it means I have just found the **right boundary** for the bar at the top of the stack. I pop that top bar. The new top of the stack automatically serves as its **left boundary**. The width is simply `current_index - new_stack_top - 1`. I calculate the area and update the global maximum.

To handle edge cases elegantly without duplicating code, I will use two defensive techniques:
1. I'll push `-1` into the stack as a **dummy left boundary**.
2. I'll append a `0` to the end of the heights array to act as a sentinel, forcing the stack to flush and calculate all remaining areas at the end of the loop.

**Complexity**
- **Time — O(N):** each bar is pushed and popped from the stack at most once.
- **Space — O(N):** the monotonic stack can hold all `N` bar indices in the worst case.

## 🛠️ Optimization
```c++
class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {

        stack<int> stk;
        stk.push(-1); // 創造左邊界
        heights.push_back(0); // 避免最後多一個迴圈判斷

        int n = heights.size();
        int res = 0;
        for (int i = 0; i < n; i++) {

            while (stk.top() != -1 && heights[stk.top()] > heights[i]) {
                int height = heights[stk.top()];
                stk.pop();
                res = max(res, (i - stk.top() - 1) * height);
            }

            stk.push(i);
        }

        heights.pop_back(); // 恢復原始輸入資料

        return res;
    }
};
```
