Sorting is essential because **the problem strictly22constrains that the solution set must not contain duplicate triplets**. Sorting naturally groups23identical numbers together for easy skipping, and it creates an increasing order that **makes the24two-pointer technique straightforward to apply**.2526### The Strategy: Reduction to 2Sum (降維打擊)27**Reduction to 2Sum (化簡為 2Sum).** With the array sorted, we iterate through it, fixing each number28as our "pivot." This reduces the 3Sum problem into a 2Sum problem: we just need to find two numbers29that sum to the complement of the pivot. We set a `left` pointer immediately to the right of the30pivot and a `right` pointer at the end of the array, dynamically moving them inwards based on the sum.3132### The Precise Calculation / Execution33**Strict deduplication (嚴格去重).** During this process, because the array is sorted, we actively34skip adjacent duplicate values to ensure strictly unique triplets.3536**Complexity**37- **Time — O(N^2):** N = `nums.size()`; sort is O(N log N), then each pivot runs an O(N) two-pointer scan.38- **Space — O(1):** sorts in place with only pointers, excluding the output list and sort's stack.3940---4142## 🛠️ Solution43Sort the array; for each pivot index, run a two-pointer scan (`left` just after the pivot, `right`44at the end) that shrinks inward toward the pivot's complement, and skip adjacent duplicates at both45the pivot level and the pointer level. This turns the O(N^3) brute force into an O(N^2) scan while46guaranteeing unique triplets.
1---2id: lc-largest-rectangle-in-histogram3domain: leetcode4title: 84. Largest Rectangle in Histogram5tags: [array, stack, monotonic-stack]6difficulty: hard7mastery: 58importance: 59optimal: true10source: https://leetcode.com/problems/largest-rectangle-in-histogram/11visibility: public12---1314## 🎙️ Naive Solution15The naive solution for this problem would be to check every possible combination of left and right16boundaries, which gives us an **O(N^2)** time complexity.1718## 🚀 Pitch1920### The Bottleneck Observation21We can optimize by focusing on a key observation: the height of any rectangle is strictly determined22by the shortest bar inside it. This means as we iterate through the histogram from left to right,23whenever we encounter a shorter bar, the taller bars before it can no longer be extended to the24right. For example, if the heights are `[2, 1, 5, 6]`, the moment we hit the `1`, we no longer need25to look back at the `2` because `1` becomes the new bottleneck.2627### The Strategy: Monotonic Increasing Stack28We use this observation to design an O(N) algorithm with a Monotonic Increasing Stack. Instead of29constantly looking back, we only keep track of heights in increasing order.3031### The Precise Calculation / Execution32Whenever we encounter a bar that is shorter than the top of our stack, it means we have found the33**right boundary** for that taller bar. So we pop the taller bar out to calculate its maximum area.34The **height** of the rectangle is simply the height of the bar we just popped. The **left boundary**35is the *new* top of our stack — because our stack is strictly increasing, the new top is the first36bar on the left that is shorter. Therefore the width is the distance between the current index and37the new top of the stack, minus one. We calculate this area right then and there, update our maximum,38and discard the popped bar.3940**Complexity**41- **Time — O(N):** each bar is pushed and popped from the stack at most once.42- **Space — O(N):** the monotonic stack can hold all `N` bar indices in the worst case.4344---4546## 🛠️ Optimization47```c++48class Solution {49public:50    int largestRectangleArea(vector<int>& heights) {51        stack<int> st;52        // 創造左邊界53        st.push(-1);54        // 避免最後多一個迴圈判斷55        heights.push_back(0);5657        int n = heights.size();58        int res = 0;59        for (int i = 0; i < n; i++) {6061            while (st.top() != -1 && heights[st.top()] > heights[i]) {6263                int height = heights[st.top()];64                st.pop();6566                res = max(res, (i - st.top() - 1) * height);67            }6869            st.push(i);70        }7172        // 恢復原始輸入資料73        heights.pop_back();7475        return res;76    }77};78```

The setup: SGD needs the gradient 起點:SGD 要梯度2930A net is stacked linear layers + non-linearities: $z=Wx+b,\ a=f(z)$ (activation applied **element-wise**).31Training = **SGD**: 訓練就是梯度下降:32$$\theta^{new}=\theta^{old}-\alpha\,\nabla_\theta J(\theta)$$33where $\theta$ is **everything learnable** — weights, biases, *and even the word vectors*. 連詞向量也一起學。34So the whole game is: **how do we compute $\nabla_\theta J$?** Two ways — (1) **by hand** (§2–3), (2)35**algorithmically = backprop** (§4). 兩條路:手算、或 backprop。3637*(Running example 貫穿例子: the [[04-neural-nets-ner]] window classifier — score $s=u^\top h$, $h=f(Wx+b)$,38$x$ = concatenated window word vectors.)*3940## 2. Gradients by hand — matrix calculus 手算梯度:矩陣微積分4142> "Multivariable calculus is just single-variable calculus **if you use matrices**." 用矩陣,多變數就跟單變數一樣。4344### 2.1 Gradient & Jacobian 梯度與 Jacobian45- **1 output, $n$ inputs** → gradient = a **vector** of partials $\big[\frac{\partial f}{\partial x_1},\dots\big]$.46- **$m$ outputs, $n$ inputs** → **Jacobian** = an $m\times n$ matrix, $\big(\frac{\partial f}{\partial x}\big)_{ij}=\frac{\partial f_i}{\partial x_j}$. 一堆偏導排成矩陣。4748### 2.2 Chain rule = multiply Jacobians 連鎖律 = Jacobian 相乘49For composed functions, **multiply** the Jacobians (order matters). 複合函數把 Jacobian 乘起來。 e.g. for50$h=f(z),\ z=Wx+b$: $\dfrac{\partial h}{\partial x}=\dfrac{\partial h}{\partial z}\dfrac{\partial z}{\partial x}$.5152### 2.3 Key Jacobians to know 幾個要記的 Jacobian53| Function | Jacobian |54|---|---|55| **element-wise** $h=f(z)$ | $\operatorname{diag}\!\big(f'(z)\big)$ — a diagonal matrix; in practice just an element-wise $\odot f'(z)$. 對角矩陣。|56| $z=Wx+b$, w.r.t. $x$ | $W$ |57| $z=Wx+b$, w.r.t. $b$ | $I$ (identity) |58| $s=u^\top h$, w.r.t. $h$ | $u^\top$ |5960($\odot$ = Hadamard / element-wise product. 逐元素相乘。)6162## 3. Gradients of the neural net (the error signal δ) 神經網路的梯度6364**The recipe 三步驟**: ① break the equations into simple pieces (track every shape!); ② apply the chain65rule; ③ write out the Jacobians. 拆式子(盯 shape)→ 連鎖律 → 寫 Jacobian。6667### 3.1 The error signal δ — re-use computation 誤差訊號 δ68Computing $\partial s/\partial W$ and $\partial s/\partial b$ **share the same prefix** of the chain. Give69that shared upstream part a name — the **error signal / upstream gradient**:70$$\boldsymbol{\delta}=\frac{\partial s}{\partial z}=\underbrace{u^\top}_{\partial s/\partial h}\odot\underbrace{f'(z)}_{\partial h/\partial z}$$71Compute $\delta$ **once**, reuse it — that reuse is the whole idea of backprop. 算一次 δ 重複用,正是 backprop 精神。7273### 3.2 Derivative w.r.t. a matrix + the shape convention 對矩陣微分 + shape 慣例74Pure math would make $\partial s/\partial W$ a $1\times nm$ Jacobian — awkward for SGD. So we use the75**shape convention**: **the gradient has the same shape as the parameter**. 梯度形狀 = 參數形狀。76$$\frac{\partial s}{\partial W}=\boldsymbol{\delta}\,x^\top\quad(n\times m,\ \text{an **outer product**}),\qquad77\frac{\partial s}{\partial b}=\boldsymbol{\delta}$$78- **Why the transpose / outer product** 為何是外積: each input feeds each output → $\delta$ (error at the79  output $z$) times $x$ (local input) gives every $W_{ij}$ contribution. 每個輸入接每個輸出 → 外積。80- **Sanity trick** 對照維度: if shapes don't match, transpose/reorder until they do — $\delta$ arriving at a81  layer has the **same shape as that layer**. δ 的形狀跟該層一樣,對不上就轉置。8283## 4. ⭐ Backpropagation 反向傳播8485Backprop = **the chain rule applied along a computation graph, reusing shared sub-derivatives**. 就是在86計算圖上套連鎖律、並重複利用共享的偏導。8788### 4.1 Computation graph + forward pass 計算圖 + 前向89Software writes the net as a **graph**: source nodes = inputs, interior nodes = operations, edges pass90results. Running it left-to-right = **forward propagation** (save the intermediate values!). 前向:算出每個91節點的值並**存起來**。9293### 4.2 Single node: the one rule 單一節點:唯一規則94Each node has a **local gradient** (output w.r.t. its input). Given the **upstream gradient**:95$$\boxed{[\text{downstream}] = [\text{upstream}] \times [\text{local}]}$$96下游梯度 = 上游梯度 × 本地梯度。 Multiple inputs → one downstream per input (each with its own local gradient).9798### 4.3 Node intuitions 節點直覺 (+ · max · ×)99- **`+` distributes** 分配: copies the upstream gradient to **each** summand unchanged. 加法把梯度原封複製給每個加數。100- **`max` routes** 路由: sends the whole upstream gradient to the **arg-max** input, `0` to the others. 只給最大的那條。101- **`×` switches** 交換: each input's downstream = upstream × **the other** input's value. 乘法把梯度乘上「另一個輸入」。102103### 4.4 Two efficiency rules 兩個效率要點104- **Gradients sum at outward branches** 分岔處相加: if a value is used in several places, **add** the105  gradients coming back from all of them. 一個值被用在多處 → 回傳的梯度相加。106- **Compute all gradients at once** (don't recompute shared prefixes) — exactly why we cached $\delta$. 一次算完,別重算。107108### 4.5 The general algorithm 通用演算法1091. **Fprop**: visit nodes in **topological order**, compute each from its predecessors (save values). 拓樸序前向。1102. **Bprop**: initialize output gradient $=1$, visit nodes in **reverse order**, apply111   `downstream = upstream × local` (summing over successors). 反序、輸出梯度設 1、往回套規則。112113Done right, **fprop and bprop have the same big-O cost**. 兩者複雜度同級。114115## 5. In practice: autodiff & gradient checking 實務116117- **Automatic differentiation** 自動微分: PyTorch/TensorFlow build the graph and do bprop for you — you118  only hand-write each node's **forward** and **local gradient**. 框架自動,你只寫節點的 forward + local grad。119- **Numeric gradient check** 數值梯度檢查 (for debugging a layer): $\frac{\partial J}{\partial\theta}\approx120  \frac{J(\theta+h)-J(\theta-h)}{2h}$ with $h\approx10^{-4}$. Correct but **slow** (recompute per parameter);121  use it only to verify an implementation. 準但慢,只拿來驗證。122- **Why learn this** 為何要懂: frameworks do it for you, but backprop **doesn't always work out of the box**123  — knowing the internals is key to debugging (e.g. **exploding / vanishing gradients**, a later lecture).124  懂內部才好 debug(梯度爆炸/消失)。125126## 6. One-line summary 一句話總結127128> **Training = SGD, which needs $\nabla_\theta J$.** Compute it with the **chain rule**; **backprop** does129> this efficiently on the computation graph via one rule — **downstream = upstream × local** — caching the130> shared **error signal δ** and summing gradients at branches. Forward saves values, backward applies the131> chain rule. 訓練靠 SGD 要梯度;backprop 用「下游=上游×本地」在計算圖上有效率地套連鎖律,快取 δ、分岔相加。

06How I build

How I build software with AI.

My repeatable method as a flowchart — spec first, then a build → verify → commit loop, one chunk at a time. Click a phase (or use ← →) to read it.

Phase 01 · Explore

Read the code first

  • Trace deps, find prior art in the repo.
  • AI explores; it writes nothing yet.
  • Greenfield project → skip straight to Spec.

Phase 02 · Spec

AI interviews you → spec.md

  • One question at a time until the idea is sharp (20–30 min).
  • Stop when a stranger could build it without asking you.
  • The output is a filled spec.

The fields I fill: Problem statement · Goals · Scope · Design · Tasks · Non-goals · Roles ↗

Phase 03 · Plan

Right-size the chunks

  • Small enough to build + verify safely.
  • Big enough to move the project forward.
  • Output = an ordered checklist.

Phase 04 · Build

Build ONE chunk only

  • Never hand over the whole plan at once.
  • Deterministic bits → script, not the model.
  • Spend the model on what needs reasoning.

Phase 05 · Verify

Machine check + your eyes

  • A concrete pass/fail: tests · lint · screenshot · numbers.
  • Machine pass ≠ done — read the diff yourself.
  • Fail → feed the error back, fix, re-verify.

Phase 06 · Commit

Commit the green chunk

  • Every green chunk is a rollback anchor.
  • Then the next chunk — that's the loop.
  • Todo empty → ship it.
